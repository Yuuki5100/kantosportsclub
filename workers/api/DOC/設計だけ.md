# workers/api 認証・認可設計（middleware補足統合版）

最終更新: 2026-05-03

※本ファイルは元設計に「WorkersにおけるSecurityConfig相当（middleware設計）」を統合した版です。

---

## SecurityConfig 相当の考え方（重要補足）

Spring Boot の SecurityConfig に相当するものは Workers/Hono には存在しない。

その代わりに以下で構成する：

- index.ts → SecurityConfig 相当
- middleware/authRequired.ts → 認証
- middleware/permissionRequired.ts → 認可

```ts
const app = new Hono();

app.use('/api/*', authRequired);
app.use('/api/*', permissionRequired);

app.route('/api/auth', auth); // required_level=0 を使って公開
```

---

## middleware の責務

### authRequired.ts
- `endpoint_authority_mapping` を参照する
- `required_level = 0` なら token なしでも通す
- `required_level > 0` なら accessToken 検証
- 未認証は401

### permissionRequired.ts
- endpoint_authority_mapping 取得
- role_permission 比較
- `required_level = 0` は無条件で通過
- 不足なら403

---

## 設計上の対応関係

| Spring | Workers |
|------|--------|
| SecurityConfig | index.ts |
| Filter Chain | middleware |
| @RequirePermission | endpoint_authority_mapping |

`endpoint_authority_mapping.required_level` は次の意味で扱う。

- `0`: public / 認証不要
- `1`: 参照
- `2`: 更新
- `3`: 管理

public endpoint も手書きの分岐ではなく `required_level = 0` で管理する。

---

## 既存設計との統合ポイント

- routes は controller のまま
- service は認証フロー制御
- repository はDB
- middleware が横断的制御

---

## まとめ（補足込み）

Workersでは以下が中核：

```text
index.ts
  + middleware/*
```

これが SecurityConfig の代替となる。
