# workers/api 権限の使い方

最終更新: 2026-05-10

この文書は、`workers/api/src/middleware/authRequired.ts` と
`workers/api/src/middleware/permissionRequired.ts` がどのように権限判定を行うか、
そして `/api/auth/status` が返すユーザー権限をどう解釈すればよいかをまとめたものです。

---

## 1. 権限判定の流れ

API リクエストは次の順で処理されます。

1. `authRequired` が `endpoint_authority_mapping` を参照する
2. `required_level = 0` なら token なしでも通す
3. `required_level > 0` なら access token を検証する
4. `permissionRequired` が `endpoint_authority_mapping` を参照する
5. ログインユーザーの権限値と `required_level` を比較する
6. 足りなければ `403 Forbidden` を返す

`/api/auth/status` はログイン中ユーザーの権限一覧を返します。
フロントはこの応答を使って画面上の「更新」ボタン表示可否を決めます。

つまり、API のアクセス制御と、画面のボタン表示は別レイヤーです。
API 側は `endpoint_authority_mapping`、画面側は `user_role_permissions` 由来の権限一覧で判定します。

---

## 2. `required_level` の意味

現在の実装では、`required_level` は次の意味で扱います。

| 値 | 意味 |
|---|---|
| 0 | public / 認証不要 |
| 1 | なし |
| 2 | 参照 |
| 3 | 更新 |

`required_level = 0` の endpoint は token なしでも通過できます。
`required_level > 0` の endpoint は、ログインユーザーが持つ権限値が `required_level` 以上なら通過できます。

例:

- `required_level = 0` の endpoint は、認証なしで通る
- `required_level = 1` の endpoint は、権限 1 / 2 / 3 で通る
- `required_level = 2` の endpoint は、権限 2 / 3 で通る
- `required_level = 3` の endpoint は、権限 3 のみ通る

---

## 3. 権限を付与したい場合

ある endpoint に対して権限を付けたい場合は、`endpoint_authority_mapping.required_level` に
必要な値を入れます。

例:

- 認証不要で公開したい場合は `0`
- 参照だけ許可したい場合は `2`
- 更新まで許可したい場合は `3`

たとえば `POST /api/media` を更新権限にしたいなら、
`endpoint_authority_mapping` に次のような行を持たせます。

```text
url = /api/media
method = POST
required_level = 3
```

---

## 4. ユーザー側の権限との対応

`user_role_permissions` の `permission_level` が、ログインユーザー側の権限値です。

`permission_level` が endpoint 側の `required_level` 以上なら通過します。
`required_level = 0` の endpoint は、ログイン状態に関係なく通過します。

例:

- ユーザーの `permission_level = 1`
  - `required_level = 1` は通る
  - `required_level = 2` は通らない
- ユーザーの `permission_level = 2`
  - `required_level = 1` / `2` は通る
  - `required_level = 3` は通らない
- ユーザーの `permission_level = 3`
  - すべて通る

---

## 5. `/api/auth/status` の返却形式

`/api/auth/status` は `authenticated`, `roleLevel`, `user`, `userPermissions` を返します。

`userPermissions` は次の形です。

```json
{
  "permissionId": 100,
  "permissionName": "NOTICE",
  "statusLevelId": 3
}
```

現在のフロントは、`userPermissions` を `permissionId -> statusLevelId` の map に変換して使います。
そのため、画面上で `NOTICE` の更新ボタンを出したい場合は、`permissionId = 100` かつ `statusLevelId = 3` が必要です。

---

## 6. 3つのIDの役割分担

この実装では、似た名前の項目が複数あるため、役割を分けて考えます。

| 項目 | 主な用途 | 判定で使うか |
|---|---|---|
| `permissions.permission_id` | 権限定義の主キー | はい |
| `permissions.permission_name` | 表示名・一覧表示のラベル | いいえ |
| `user_role_permissions.resource` | `/api/auth/status` が読むユーザー権限の元データ | はい |
| `user_role_permissions.permission_level` | ユーザー側の権限レベル | はい |
| `master_menu_function.id` | endpoint と機能グループの対応付け | いいえ |
| `master_menu_function.name` | 画面表示用の機能名 | いいえ |
| `endpoint_authority_mapping.menu_function_id` | endpoint が属する機能グループ | いいえ |
| `endpoint_authority_mapping.required_level` | endpoint に必要な権限レベル | はい |

補足:

- `RequirePermission(permissionId = ..., statusLevelId = ...)` の `permissionId` は、`permissions.permission_id` を指します。
- `permissionName` は `auth/status` の表示用フィールドとしても返しますが、画面判定の本体は `permissionId` です。
- `master_menu_function` は、権限一覧や endpoint の機能グルーピングのためのマスタです。
- 認可の本体は `permission_id` と `status_level_id` の組み合わせです。

---

## 7. endpoint_authority_mapping に載せる単位

権限判定は HTTP メソッドと URL の組み合わせで行います。

例:

- `GET /api/media`
- `POST /api/media`
- `GET /api/media/*`
- `PUT /api/media/*`

つまり、同じ URL でも `GET` と `POST` は別設定です。

---

## 8. 403 になる条件

次のどれかに当てはまると `403` になります。

- `endpoint_authority_mapping` に該当行がない
- ユーザーの権限値が `required_level` に届いていない
- access token はあるが、ログインユーザーの権限が不足している

---

## 9. public 扱いの endpoint

`required_level = 0` の endpoint は public 扱いです。

これらも `endpoint_authority_mapping` に明示的に載せます。
手書きの public path 分岐は使いません。

---

## 10. 実運用での設定例

### 認証不要で公開したい endpoint

```text
method = GET
required_level = 0
```

### 参照だけ許可したい endpoint

```text
method = GET
required_level = 2
```

### 更新まで許可したい endpoint

```text
method = POST
required_level = 3
```

### 管理者のみ許可したい endpoint

```text
method = DELETE
required_level = 3
```

---

## 11. 注意点

- `endpoint_authority_mapping` は endpoint ごとの設定です
- ページ単位ではなく API 単位で判定されます
- `admin` ユーザーは現状の seed では多くの endpoint を通ります
- public endpoint は `required_level = 0` で表現します
- `user_role_permissions` は `/api/auth/status` の元データとして使います
- `permissions` と `master_menu_function` は別テーブルで、用途も別です
- `403` が出ない場合は、まず `required_level` とユーザー権限値を確認します
